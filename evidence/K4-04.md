# K4-04 — Учебный инцидент

Группа: ИТ-9.24.2  
Код студента: 12072008

## 1. Цель

Воспроизвести отказ API, определить причину по логам и метрикам, восстановить сервис и проверить сохранность данных.

## 2. Исходное состояние

Перед инцидентом работали контейнеры web, api, Prometheus и Grafana.

В приложении присутствовала заявка №1 «Не работает экран».

Адрес проверки: http://localhost:8080/api/requests

## 3. Воспроизведение сбоя

API остановлен командой:

```bash
docker compose -f compose.student.yaml stop api
```

При обращении к `/api/requests` получен ответ:

```json
{
  "error": "upstream_unavailable",
  "request_id": "1b1441bd"
}
```

HTTP-статус: 503 Service Unavailable.

Web продолжал работать, но не мог обратиться к API.

## 4. Диагностика

В Prometheus выполнен запрос:

```promql
devops_http_requests_total{role="web",status="503"}
```

Получено значение 1 — зафиксирован неуспешный запрос.

Также использован запрос:

```promql
up{job="workshop"}
```

Метрика `up` показывает успешность сбора метрик с сервисов: 1 — успешно, 0 — неуспешно.

Для изучения ошибки выполнена команда:

```powershell
docker compose -f compose.student.yaml logs --no-color web | Select-String 'upstream_unavailable'
```

В логе найдено событие `upstream_unavailable` с идентификатором `1b1441bd` и сообщением `No address associated with hostname`.

Время события: 23.11.2026, 22:15:45 UTC.

Причина: остановка контейнера api привела к недоступности зависимости для web.

## 5. Восстановление

API запущен командой:

```bash
docker compose -f compose.student.yaml start api
```

Состояние проверено:

```bash
docker compose -f compose.student.yaml ps
```

Контейнер api вернулся в состояние healthy.

В Prometheus запрос `up{job="workshop"}` вновь показал:

- api:8000 — 1
- web:8000 — 1

## 6. Проверка заявок

После восстановления повторно открыт `/api/requests`.

Старая заявка №1 сохранилась.

Создана новая заявка №2 «Не заряжается».

Результат: `total = 2`.

Это подтверждает восстановление пользовательского сценария и сохранность данных в Docker volume.

## 7. Хронология инцидента

1. Исходное состояние — сервисы работали, существовала заявка №1.
2. Сбой — контейнер api остановлен.
3. Симптом — web возвращает HTTP 503.
4. Диагностика — в метриках обнаружен ответ 503, в логах найдено событие upstream_unavailable.
5. Причина — недоступность API.
6. Действие — выполнен запуск остановленного контейнера.
7. Проверка — оба сервиса доступны, заявка №1 сохранена, заявка №2 создана.

## 8. Вывод

В ходе работы был воспроизведён и устранён отказ API.

Для диагностики использованы HTTP-ответы, логи Docker и метрики Prometheus.

Выполнено восстановление процесса, а не rollback версии: образ и конфигурация приложения не менялись.

Помощь ИИ использовалась для объяснений и оформления отчёта. Результаты сопоставлены с фактическими проверками.
