# DevOps

Курс для **9.23.1 и 9.23.2**. **28 академических часов · 4 КТ · 100 баллов**.

Мы работаем с готовым сервисом «Мастерская»: страница отправляет заявку через `web`, компонент `api` сохраняет её. Ваша задача — обеспечить запуск, автоматические проверки, наблюдение за состоянием и восстановление после сбоя. Писать приложение с нуля не нужно.

## С чего начать

1. Прочитайте [подготовку и первый запуск](docs/START.md). Docker должен быть установлен и подготовлен преподавателем; права администратора не нужны.
2. Создайте свою копию репозитория по [инструкции сдачи](docs/SUBMISSION.md).
3. Откройте теорию нужной КТ, затем её задания. В каждой работе указаны шаги, подтверждения и баллы.
4. Сохраните результат в своей копии и отправьте преподавателю ссылку на pull request.

## Требования к работам и оцениванию

- **Каждая работа оценивается внутри своей КТ.** Выполненные критерии дают частичный балл; полного балла только за статус «сдано» нет.
- До выполнения вы видите максимум, критерии и ожидаемый результат. Общие правила — в [оценивании](docs/GRADING.md).
- Сдаётся работающая конфигурация/код и краткое подтверждение в `evidence/`. Один скриншот без файлов и объяснения недостаточен.
- Нужно уметь объяснить свою работу и выполнить небольшое изменение. Готовый шаблон и помощь разрешены с указанием источника; они не заменяют проверку понимания.
- Работу можно доработать по замечаниям. Повторная попытка повышает балл той же работы, а не добавляет вторую сумму.
- Присутствие, количество разговоров и число коммитов баллов не дают. Содержательные активности уже включены в критерии работ.
- Баллы выставляет преподаватель в отдельном Google-журнале. Ссылка будет предоставлена преподавателем; журнал с персональными результатами в этот репозиторий не входит.
- Сроки по группам и перевод баллов в отметку объявляет преподаватель по расписанию и правилам колледжа. Здесь нет выдуманных дат и проходных порогов.

## Мой результат

Группа: ИТ-9.24.2  
Код студента: 12072008

### 1. Сборка и запуск

Из корня репозитория собрать Docker-образ:

```bash
docker build -f lab/Dockerfile -t devops-student:v1 lab
```

Запустить приложение и мониторинг:

```bash
docker compose -f compose.student.yaml --profile monitoring up -d
docker compose -f compose.student.yaml --profile monitoring ps
```

Адреса:
- Приложение: http://localhost:8080
- Проверка процесса: http://localhost:8080/health
- Список заявок: http://localhost:8080/api/requests
- Prometheus: http://localhost:9090
- Grafana: http://localhost:3000

### 2. Автоматические проверки и Docker

Исходники хранятся в GitHub. Workflow `.github/workflows/student-ci.yml` запускает тесты, затем собирает Docker-образ.

Задача build зависит от test через `needs: test`.

Успешный CI: https://github.com/spaeeell/DevOps-course/actions/runs/42379799167

Commit SHA: `19fa231ee13ac4ea4b6773337861dec8e797ba35`.

### 3. Сеть и данные

Контейнер web доступен на порту 8080 компьютера и обращается к api по внутреннему адресу `http://api:8000`.

API сохраняет заявки в именованный Docker volume `requests`. При обычной остановке и повторном запуске контейнера данные сохраняются.

### 4. Мониторинг

Prometheus собирает метрики с `api:8000` и `web:8000`.

Запрос `up{job="workshop"}` показывает доступность целей сбора метрик.

Grafana визуализирует скорость успешных запросов:

```promql
rate(devops_http_requests_total{role="web",status="200"}[1m])
```

Dashboard экспортирован в [K4-02-dashboard.json](evidence/K4-02-dashboard.json).

### 5. Ansible

Сборка образа Ansible:

```bash
docker build -f docker/ansible.Dockerfile -t devops-course-ansible:base .
```

Применение конфигурации:

```bash
docker compose -f compose.student.yaml run --rm ansible banner.yml
```

Playbook `ansible/banner.yml` создаёт `/data/banner.txt` с правами 0644 и владельцем 10001.

Повторный запуск без изменений даёт `changed=0`. Результат доступен по адресу http://localhost:8080/api/banner.

### 6. Инцидент и восстановление

При остановке API веб-приложение возвращало HTTP 503. В логах обнаружено событие `upstream_unavailable`, а Prometheus зафиксировал недоступность API.

Восстановление:

```bash
docker compose -f compose.student.yaml start api
```

После восстановления старая заявка сохранилась, новая успешно создана.
