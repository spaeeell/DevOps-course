# K4-02 — Prometheus и Grafana

Группа: ИТ-9.24.2  
Код студента: 12072008

## 1. Цель

Настроить мониторинг приложения через Prometheus и Grafana, изучить метрики и построить график HTTP-запросов.

## 2. Запуск мониторинга

Использована команда:

```bash
docker compose -f compose.student.yaml --profile monitoring up -d
```

Проверено состояние контейнеров:

```bash
docker compose -f compose.student.yaml --profile monitoring ps
```

Результат: контейнеры api, web, prometheus и grafana запущены.

## 3. Проверка Prometheus

Адрес: http://localhost:9090

Запрос:

```promql
up{job="workshop"}
```

Результат:

- api:8000 — 1
- web:8000 — 1

Обе цели доступны для сбора метрик.

Значение `up = 1` означает успешный сбор метрик, а `up = 0` — ошибку сбора. Эта метрика сама по себе не гарантирует успешное выполнение пользовательской операции.

## 4. Счётчик HTTP-запросов

Использован запрос:

```promql
devops_http_requests_total{role="web",status="200"}
```

Метрика показывает накопленное количество HTTP-ответов web со статусом 200 с момента запуска процесса.

Во время проверки наблюдалось значение 6.

## 5. Скорость запросов

Использован запрос:

```promql
rate(devops_http_requests_total{role="web",status="200"}[1m])
```

Функция `rate` вычисляет среднюю скорость увеличения счётчика за последнюю минуту.

Для создания нагрузки многократно обновлялся список заявок в браузере.

В Grafana наблюдался рост скорости приблизительно до 0,56 запроса в секунду, затем значение снизилось после прекращения нагрузки.

## 6. Панель Grafana

Адрес: http://localhost:3000

Источник данных: Workshop Prometheus.

Название Dashboard: DevOps KT4 — Monitoring.

Название панели: Скорость успешных HTTP-запросов web.

Тип визуализации: Time series.

Единица измерения: requests/sec.

Экспорт Dashboard сохранён в файле `evidence/K4-02-dashboard.json`.

## 7. Вывод

Prometheus успешно собирает метрики с web и api. Grafana отображает изменение скорости HTTP-запросов при создании нагрузки.

Счётчик показывает накопленное число успешных ответов, а `rate` позволяет оценить интенсивность запросов.

После перезапуска приложения счётчик может обнулиться, поскольку хранится в памяти процесса. При этом сохранённые заявки не обязательно теряются, так как данные приложения хранятся отдельно.

При подготовке отчёта использована помощь ИИ для объяснений и оформления. Результаты подтверждены фактическими проверками.
