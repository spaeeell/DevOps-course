# K4-03 — Ansible и повторный запуск

Группа: ИТ-9.24.2  
Код студента: 12072008

## 1. Цель работы

Изучить управление состоянием файлов через Ansible, проверить идемпотентность и изменение конфигурации приложения без пересборки образа.

## 2. Подготовка

Собран Docker-образ Ansible:

```bash
docker build -f docker/ansible.Dockerfile -t devops-course-ansible:base .
```

Ansible выполняется внутри Docker-контейнера. В учебном стенде используется inventory `localhost` и локальное подключение `connection: local`, поэтому SSH не требуется.

Для удалённого сервера понадобились бы его адрес в inventory, SSH-доступ и соответствующие учётные данные.

## 3. Проверка demo.yml

Команда:

```bash
docker compose -f compose.student.yaml run --rm ansible demo.yml
```

Первый запуск:

- ok=1
- changed=1
- failed=0

Второй запуск:

- ok=1
- changed=0
- failed=0

Повторное применение не изменило уже настроенный файл.

Это демонстрирует идемпотентность Ansible.

## 4. Настройка banner.yml

Создан файл `ansible/banner.yml`.

Добавлена переменная:

```yaml
workshop_message: "ИТ-9.24.2 | 12072008"
```

Модуль `ansible.builtin.copy` управляет файлом `/data/banner.txt`.

Использованы настройки:

- mode: 0644
- owner: 10001
- group: 10001

Права 0644 позволяют владельцу читать и изменять файл, остальным — только читать.

UID/GID 10001 соответствует пользователю приложения в учебном контейнере.

## 5. Применение конфигурации

Выполнена команда:

```bash
docker compose -f compose.student.yaml run --rm ansible banner.yml
```

После применения открыт адрес:

`http://localhost:8080/api/banner`

Получен ответ:

```json
{"message": "ИТ-9.24.2 | 12072008"}
```

## 6. Изменение сообщения

Значение переменной изменено:

```yaml
workshop_message: "ИТ-9.24.2 | 12072008 | Ansible OK"
```

После повторного применения playbook API вернул:

```json
{"message": "ИТ-9.24.2 | 12072008 | Ansible OK"}
```

Изменение выполнено без пересборки Docker-образа.

## 7. Вывод

Ansible позволяет описывать необходимое состояние файлов в YAML и автоматически применять конфигурацию.

На примере demo.yml подтверждена идемпотентность: повторный запуск не вызвал изменений.

Через banner.yml выполнено управление содержимым файла, который используется API приложения.

При подготовке отчёта использовалась помощь ИИ для объяснений и оформления. Практические результаты проверены самостоятельно.
