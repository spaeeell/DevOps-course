# K4-01 — Логи и доступность

Группа: ИТ-9.24.2  
Код студента: 12072008

## 1. Цель работы

Проверить доступность приложения, создать заявку и сопоставить действия пользователя с логами контейнеров web и api.

## 2. Запуск приложения

Собран Docker-образ:

```bash
docker build -f lab/Dockerfile -t devops-student:v1 lab
```

Запущены сервисы:

```bash
docker compose -f compose.student.yaml up -d
docker compose -f compose.student.yaml ps
```

Результат: контейнеры `api` и `web` запущены, имеют статус `healthy`.

## 3. Создание заявки

Через браузер открыт адрес `http://localhost:8080/`.

Создана заявка «Не работает экран».

Результат:
- Номер заявки: 1
- Тип: screen
- HTTP-статус создания: 201
- Количество заявок: 1

Время создания: 23.11.2026, 21:14:56 UTC.

## 4. Анализ логов

Для просмотра логов использованы команды:

```bash
docker compose -f compose.student.yaml logs --tail=30 web
docker compose -f compose.student.yaml logs --tail=30 api
```

Для поиска событий заявки использована фильтрация PowerShell:

```powershell
docker compose -f compose.student.yaml logs --no-color web | Select-String 'POST|/api/requests'
docker compose -f compose.student.yaml logs --no-color api | Select-String 'POST|/api/requests'
```

В логах `web` обнаружено:

```text
2026-11-23T21:14:56.732475+00:00
POST /api/requests HTTP/1.1 — 201
```

В логах `api` обнаружено:

```text
2026-11-23T21:14:56.732163+00:00
POST /api/requests HTTP/1.1 — 201
```

После создания заявки оба сервиса зарегистрировали получение списка:

```text
GET /api/requests HTTP/1.1 — 200
```

Время событий совпадает с отправкой заявки в браузере. Это подтверждает прохождение запроса через web к api и получение успешного ответа.

Дополнительно в обоих контейнерах наблюдались регулярные запросы `GET /health` со статусом 200.

## 5. Проверка доступности

Адрес: `http://localhost:8080/health`

Ответ:

```json
{"process":"running","role":"web"}
```

Адрес: `http://localhost:8080/api/requests`

Получен список с заявкой №1, типом `screen` и полем `total: 1`.

`/health` подтверждает работу процесса web, но не проверяет всю цепочку создания заявки.

`/api/requests` проверяет взаимодействие web с api и получение данных.

При отказе API запрос `/health` у web может продолжать выполняться, а обращение к `/api/requests` обнаружит недоступность зависимости.

## 6. Вывод

Приложение успешно запущено через Docker Compose. Создана заявка №1, найдено соответствие между временем действия в браузере и логами web и api.

Подтверждена разница между проверкой состояния отдельного процесса и проверкой пользовательского сценария с зависимостью от API.

При оформлении отчёта использована помощь ИИ. Результаты проверены по фактическим выводам команд и ответам приложения.
