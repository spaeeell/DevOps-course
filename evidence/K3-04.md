# K3-04 — Сборка после тестов

Группа: ИТ-9.24.2  
Код студента: 12072008

## 1. Что выполнено

В `.github/workflows/student-ci.yml` добавлен отдельный job `build`, который запускается после успешного выполнения job `test`.

Для этого используется зависимость:

```yaml
build:
  runs-on: ubuntu-latest
  needs: test
```

Внутри `build` выполняется `actions/checkout` для получения исходного кода и сборка Docker-образа:

```bash
docker build -f lab/Dockerfile -t devops-student:${{ github.sha }} lab
```

`${{ github.sha }}` — SHA проверяемой ревизии, который используется в теге образа.

## 3. Проверка зависимости needs: test

Для проверки в `tests/test_app.py` временно изменено ожидаемое значение HTTP-статуса с `201` на `200`.

Ссылка на ошибочный запуск: https://github.com/spaeeell/DevOps-course/actions/runs/42378373479

Событие: push  
Commit SHA: `c26b36314531873c610eabb62a68ea69f54004bb`

Результат:
- test — failed
- build — skipped

Тест завершился ошибкой, потому что приложение возвращало HTTP 201, а тест ожидал 200.

Из-за зависимости `needs: test` сборка Docker-образа не запускалась.

В тесте восстановлено правильное ожидание HTTP-статуса `201`.

Результат:
- test — success

В одном запуске workflow успешно выполнились тестирование и сборка образа.

## 5. Вывод

В работе настроена зависимость сборки Docker-образа от успешного прохождения автоматических тестов.

Эксперимент подтвердил, что при ошибке в тестах job `build` получает статус `skipped`. После исправления тестов сборка снова выполняется.

Собранный Docker-образ остаётся во временной среде runner. Поскольку мы не отправляем его в Docker Registry, после удаления runner образ не сохраняется как доступный для последующего развёртывания.

При подготовке отчёта использована помощь ИИ для оформления и объяснений; результаты проверены по GitHub Actions.
