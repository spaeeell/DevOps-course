## 1. Разница между CI, Continuous Delivery и Continuous Deployment

**CI (Continuous Integration)** — автоматическая проверка изменений после отправки кода в репозиторий. Помогает обнаруживать ошибки до объединения изменений.

**Continuous Delivery** — автоматические тесты и сборка подготавливают приложение к выпуску, но решение о выпуске принимается отдельно.

**Continuous Deployment** — после успешных проверок новая версия автоматически разворачивается в рабочей среде.

В нашем проекте GitHub Actions будет запускать тесты Python и собирать Docker-образ. Само приложение автоматически разворачиваться не будет.

## 2. Схема работы

```text
Создание ветки kt3
        |
        v
Изменение файлов проекта
        |
        v
git push
        |
        v
GitHub Actions (CI)
        |
        v
Автоматические тесты
        |
        v
Сборка Docker-образа
        |
        v
Pull Request в main своей копии
        |
        v
Проверка и исправление ошибок
        |
        v
Слияние в main
        |
        v
Отдельное решение о выпуске
```

Проверки запускаются при событиях `push` и `pull_request`. После создания или обновления PR выполняется дополнительная проверка до слияния.

Автоматическое тестирование выполняется командой:

```bash
python -m unittest discover -s tests -p test_app.py -v
```

Если тест завершится ошибкой, GitHub Actions покажет неуспешный запуск. Разработчик увидит причину в логах и сможет исправить её до слияния.

## 3. Сравнение с Git-flow

В нашей работе используется простая схема: короткая ветка → Pull Request → проверка → слияние в main.

Git-flow предполагает дополнительные ветки `develop`, `release`, `feature` и `hotfix`.

Для небольшого учебного проекта простая схема удобнее, потому что требует меньше операций с ветками, а изменения быстрее проходят проверку.

## 4. Вывод

CI помогает автоматически находить ошибки. Continuous Delivery подготавливает приложение к выпуску. Continuous Deployment автоматически разворачивает проверенную версию.

Сборка Docker-образа сама по себе не считается автоматическим deployment, поскольку образ ещё не развёрнут в рабочей среде.

При подготовке отчёта использована помощь ИИ для структуры и объяснений; требования сопоставлены с практической работой преподавателя.
