- Что сделано: Создан файл `compose.student.yaml`. Сервисы `api` и `web` переведены на собственный образ `devops-student:v1`. Проверена работа приложения и сохранность заявок после пересоздания контейнера `api`.



- Команды и существенный вывод:



```powershell

Copy-Item .\compose.yaml .\compose.student.yaml

docker compose stop

docker compose -f compose.student.yaml config

docker compose -f compose.student.yaml up -d

docker compose -f compose.student.yaml ps

docker compose -f compose.student.yaml up -d --no-deps --force-recreate api

docker compose -f compose.student.yaml ps

```



В `compose.student.yaml` для сервисов `api` и `web` указан образ:



```yaml

image: devops-student:v1

```



До пересоздания `api` были созданы заявки:



```text

№1 — Не работает экран

№2 — Не заряжается

```



После выполнения:



```powershell

docker compose -f compose.student.yaml up -d --no-deps --force-recreate api

```



заявки №1 и №2 сохранились.



После этого была успешно создана новая заявка:



```text

№3 — Не запускается программа

```



- Ожидал: После пересоздания контейнера `api` старые заявки должны сохраниться, так как данные находятся в Docker volume.



- Получил: После пересоздания `api` заявки №1 и №2 остались в списке, а новая заявка №3 успешно создалась.



- Почему это подтверждает результат: Контейнер `api` был пересоздан, но данные не исчезли. Это подтверждает, что заявки хранятся в Docker volume `requests`, а не только в изменяемом слое контейнера.



- Порты и сеть: Браузер обращается к `localhost:8080`, который перенаправляется на порт `8000` контейнера `web`. Внутри сети Docker сервис `web` обращается к API по адресу:



```text

http://api:8000

```



- Ответ на вопрос из задания: Нельзя хранить базу только в изменяемом слое контейнера, потому что при пересоздании контейнера этот слой заменяется и данные могут быть потеряны. Docker volume хранит данные отдельно от жизненного цикла контейнера.



- Инструкция запуска:



```powershell

docker compose -f compose.student.yaml up -d

```
