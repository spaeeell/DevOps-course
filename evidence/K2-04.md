# Работа K2-04



- Группа: ИТ-9.24.2

- Код студента: 12072008

- Что сделано: Запущен локальный Docker Registry. Для образа `devops-student:v1` создан новый тег `localhost:5000/workshop:v1`. Образ отправлен в registry через `docker push`, затем получен обратно через `docker pull`. Проверены digest и свойства образа.



- Команды и существенный вывод:



```powershell

docker compose --profile registry up -d registry

docker tag devops-student:v1 localhost:5000/workshop:v1

docker push localhost:5000/workshop:v1

docker pull localhost:5000/workshop:v1

docker image inspect localhost:5000/workshop:v1

```



При выполнении `docker push` получен digest:



```text

sha256:e847acb6ac211519b56d88c2079cd63f834c0559283240502a3e1ab1c564260b

```



При выполнении `docker pull` получен тот же digest:



```text

sha256:e847acb6ac211519b56d88c2079cd63f834c0559283240502a3e1ab1c564260b

```



Статус:



```text

Image is up to date for localhost:5000/workshop:v1

```



В результате `docker image inspect` подтверждены оба тега:



```text

devops-student:v1

localhost:5000/workshop:v1

```



- Ожидал: Образ должен получить новый тег, успешно отправиться в локальный registry и затем успешно скачаться обратно.



- Получил: `push` и `pull` прошли успешно. Digest образа при отправке и получении совпал.



- Почему это подтверждает результат: Совпадающий digest подтверждает, что из registry был получен тот же образ, который был туда отправлен.



- Ответ на вопрос из задания: Команда `docker push` не запускает сервис. Она только отправляет Docker-образ в registry. Чтобы запустить приложение, после получения образа нужно отдельно создать и запустить контейнер.



- Объяснение tag и digest: `tag` — это удобное имя версии образа, например `v1`. Такой тег можно изменить или переназначить. `digest` — это идентификатор конкретного содержимого образа. Если содержимое образа изменится, digest тоже изменится.
